# StudyQuest Phase 5a: XP, Levels, Coins and Badges Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every run has its own XP, level and coins, and earns badges. Some badges are won within the run; three permanent ones are won when a run closes. All of it is derived from the log and shown on Home, Prestige Up and the Hall.

**Architecture:** A new pure module, `src/core/rewards.ts`, computes everything from the replayed `State`. No event, replay or log changes. The UI only reads the results.

**Tech Stack:** TypeScript 7, Obsidian API, esbuild, Vitest 5 (`TZ=America/New_York`). Unchanged.

**Spec:** `docs/superpowers/specs/2026-11-18-phase-5a-xp-design.md`

## Global Constraints

- Nothing under `src/core/` imports `obsidian`. No new events; every existing test stays green unchanged.
- XP weights: lecture 10, lab 15, assignment 40, exam (sat) 50, reading 5 per live bump plus 20 when finished, progress 15 when finished. Coins equal XP.
- Level step from *L* to *L + 1* costs `50 + 10 × (L − 1)` XP. Every run starts at level 1 and there's no cap.
- Badge names, exactly: `Course complete`, `Lecture sweep`, `First prestige`, `Tier 3 run`, `Tier 5 run`.
- Permanent badges are ordered by `closed.at`, then by run id. Tiers come from `closed.tier`. Tier 3 run means `tier >= 3`, and Tier 5 run means `tier === 5`.
- Version `0.5.0` in `manifest.json` and `package.json`; add `"0.5.0": "1.7.2"` to `versions.json`.
- Every commit message ends with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **A run with no objectives, or a course with none.** Expected: level 1, 0 XP, 0 coins, and no Course complete badge for an empty course. → Task 1 and Task 2 tests.
2. **Two runs closed by the same daily check (same `closed.at`).** The permanent badge goes to the run with the smaller id, and only that one. → Task 2 test.
3. **A reading finished after bumps.** It keeps its bump XP and adds 20. A third undo is impossible, so the XP can't drop after finishing. → Task 1 test.
4. **Switching Home between runs where one has badges and one doesn't.** The top row mustn't change height (the user asked for this with the exam-week line). → Task 3 reserves the badge line's space; the manual check covers it.
5. **A closed run shown in Home's "is closed" box.** The box shows the final level. → Task 3, manual check.

### Task 1: XP, coins and levels

**Files:**
- Create `src/core/rewards.ts`.

**Interfaces (produced):**
- `XP = { lecture: 10, lab: 15, assignment: 40, exam: 50, readingBump: 5, readingFinished: 20, progress: 15 } as const`.
- `objectiveXp(o: ObjectiveState): number`.
  - A reading earns `5 × o.bumps.length`, plus 20 if `o.completed`.
  - Any other kind earns its weight if `o.completed`, and 0 otherwise.
- `interface LevelInfo { level: number; xpIntoLevel: number; xpForNextLevel: number }`.
- `levelFor(xp: number): LevelInfo`.
- `interface RunRewards { xp: number; coins: number; level: LevelInfo }`.
- `runRewards(s: State, run: string): RunRewards`, where `coins === xp`.

- [ ] **Step 1: Write failing tests,** using the `ev` fixtures.
  - Lecture, lab and assignment, each completed with evidence, earn 10, 15 and 40.
  - An exam completed as `sat` earns 50.
  - An open lecture earns 0.
  - A reading with levels earns 15 after three bumps. After an undo it earns 10. Bumping twice then finishing earns 30.
  - A legacy reading (no levels) earns 20 when finished.
  - A progress objective earns 15 when finished, and 0 while only its steps are checked.
  - `levelFor`:

    - A closed run's stains add nothing.

### Task 2: Badges

**Files:**
- Modify `src/core/rewards.ts`.
- Test in `tests/core/rewards.test.ts`.

**Interfaces (produced):**
- `type BadgeId = "course-complete" | "lecture-sweep" | "first-prestige" | "tier-3" | "tier-5"`.
- `BADGE_NAMES: Record<BadgeId, string>`.
- `interface Badge { id: BadgeId; name: string; course?: string }`. In-run badges carry the course code.
- `runBadges(s: State, run: string): Badge[]` returns the in-run badges in course order. For each course, Course complete comes before Lecture sweep.
  - **Course complete:** the course has at least one objective, and all of them are completed.
  - **Lecture sweep:** the course has at least one lecture, and all its lectures are completed.
- `permanentBadges(s: State): (Badge & { run: string })[]` gives, for each permanent badge, the first closed run that qualifies. Closed runs are ordered by `closed.at`, then by id. Badges never earned are left out.
- `badgesEarnedBy(s: State, run: string): Badge[]` returns `runBadges` followed by the permanent badges credited to that run.

- [ ] **Step 1: Write failing tests.**
  - A course with every objective done gets Course complete. Adding a new objective takes it away again.
  - A course with all its lectures done but an assignment still open gets only Lecture sweep.
  - A course with no lectures never gets Lecture sweep, even when complete.
  - An empty course gets no badges.
  - With two closed runs, A then B, where A is Tier 1 and B is Tier 5:
    - First prestige goes to A;
    - Tier 3 run and Tier 5 run go to B;
    - `badgesEarnedBy(B)` includes both of those.
  - For two runs closed with the same `t`, the badges go to the run with the smaller id.
  - With no closed runs, `permanentBadges` is empty.
  - An Unranked (tier 0) close still earns First prestige.
- [ ] **Step 2: Confirm the tests fail.**
- [ ] **Step 3: Implement.** Reuse `courseObjectives` from `derive.ts`.
- [ ] **Step 4: Run `npm test`** (green) and `npm run build` (clean).
- [ ] **Step 5: Commit** with the message `feat(core): in-run and permanent badges`.
